## 0. 本轮已确认的产品决策（权威基线）

| ID | 决策 | 交互与状态约束 |
|---|---|---|
| D-01 | [已确认] 数字登录账号由 `100` 起逐次递增，**没有固定的三位数或人数上限** | `999 → 1000`、`9999 → 10000`；展示与输入均不按三位数限制；账号不可自选或回收复用 |
| D-02 | [已确认] 不使用邮箱、短信、第三方登录 | 注册、登录、找回及审核页面不得要求邮箱或手机号 |
| D-03 | [已确认] 注册默认 User + Pending，管理员激活后才可正式使用 | Pending 仅可查看自身审核状态和退出，不可调用 AI / 使用正式能力 |
| D-04 | [已确认] 密码**至少 6 位** | 前后端一致按至少 6 位校验；生产必须同时具备登录限流与防爆破控制；不得悄悄改为 8 位 |
| D-05 | [已确认] 密码找回采用**一次性恢复码 + 管理员辅助** | 用户通过恢复码自助改密；没有有效恢复码时只能走管理员可信人工核验，不可凭数字账号直接重置 |
| D-06 | [已确认] 普通用户**只能连接平台已批准的 MCP Server** | 用户端不得出现任意 URL 新建 MCP Server 入口；只能连接已批准且可授权的服务 |
| D-07 | [已确认] 一个统一用户体系，角色为 User / Creator / Admin | 管理员与普通用户使用同一认证会话；管理功能只按服务端权限开放 |
| D-08 | [已确认] 正式工作台不得以模拟能力或模拟回复伪装真实可用 | 无真实能力时展示诚实空状态；示例内容与正式资源隔离 |

> 安全备注：6 位为产品最低长度，不等于低强度密码安全。应有常见弱密码拦截、登录限流、失败延迟、注册防刷、管理员重置审计；具体强度与阈值由安全实施规格细化。密码本身与恢复码都不能明文持久化或进入日志。

## 1. 体验目标与信息架构

### 1.1 设计目标

- **入口可发现**：游客找得到登录/注册；Admin、Creator 找得到自己被授权的管理入口。
- **身份一致**：同一账号覆盖用户工作台和有权限的管理控制台，不出现两套互相独立的管理员密码。
- **状态可解释**：每个阻断动作都说明原因及下一步（待激活/未授权/未就绪/已停用等），不以“未知错误”代替。
- **个人数据有归属**：跨设备登录看到本人数据；旧匿名数据只能经明确认领绑定。
- **能力真的可用**：已发布、可见、可执行、用户已授权分别判定；不能把模拟连接/模拟回复标成成功。
- **小步闭环**：用户注册→激活→使用，Creator 创建→Admin 发布→用户授权/执行→运行治理。

### 1.2 三个产品区域

| 区域 | 入口 | 主要用途 | 典型主体 |
|---|---|---|---|
| 个人网站 | `/` | 作品/RAG/3D/智能助手产品介绍 | 所有人 |
| 智能助手用户工作台 | `/assistant` | 聊天、能力目录、文件、个人中心 | Active 用户 |
| 智能助手管理控制台 | `/assistant/admin` | 用户权限、能力配置/审核/发布、系统运营 | Active 且有管理权限的用户 |

同仓库与同部署不改变用户对于这三个区的产品感知。管理控制台必须有独立导航布局；普通用户工作台不能继承管理后台的菜单。

## 2. 全局导航与入口

### 2.1 工作台顶部导航

用户工作台顶部持续提供：产品标识、（按布局）当前区域、账户头像菜单。账户菜单内容按服务端确认的身份显示：

| 项目 | Guest | User | Creator | Admin |
|---|:---:|:---:|:---:|:---:|
| 登录、注册 | ✓ | — | — | — |
| 个人中心、账户安全 | — | ✓ | ✓ | ✓ |
| 能力创作中心 | — | — | ✓ | 可选 |
| 管理控制台 | — | — | — | ✓ |
| 退出登录 | — | ✓ | ✓ | ✓ |

- **Admin** 的“管理控制台”必须在账户菜单**和**个人中心两个位置可见；不要求手输 URL。
- **Creator** 显示“能力创作中心”，进入同一管理布局的权限限定视图。
- 管理端顶部/侧边始终有“返回用户工作台”。
- 帐号的角色刚被更改时，导航刷新权限；越权路由仍由后端拒绝，不能只隐藏菜单。
- 移动端账户入口不得只依靠悬停，菜单可通过点击/键盘打开。

### 2.2 侧栏基本结构

**用户端**：新聊天、搜索/历史、Agent、Tool、Skill、MCP、文件库；在屏幕较窄时合并为抽屉。**管理端**：总览、用户与权限、AI 资源、能力中心（四类）、发布中心、运行中心、系统设置；按权限过滤模块。不要把管理菜单混入用户端聊天侧栏。

### 2.3 直接访问和 `returnTo`

- 未登录访问受保护页 → `/assistant/login?returnTo=<安全站内路径>`；仅允许白名单内站内相对路径，禁止外站跳转。
- 登录后为 Pending → `/assistant/pending`，不因 `returnTo` 绕过限制。
- 登录后为 Active 且有权限 → 返回目标页；无权限 → 403 页面或无权提示（禁止循环跳转）。
- 未知、已删除或不属于本人的私人资源 → 404，避免通过 403 泄露其存在性。
- `/assistant` 为状态分流入口，而非在身份未校验完成前先闪现示例聊天页面。

## 3. 账号体系：页面级交互规格

### 3.1 游客欢迎页 `/assistant`

**页面目标**：清楚回答产品用途、如何开始、有哪些真实功能。

**主区域顺序**：品牌/一句话价值 → “登录”与“创建账号”主操作 → 真实可用功能简介 → 示例内容（独立、明确说明演示） → 产品使用须知。

**状态与交互**：

| 状态 | UI 表现 | 允许操作 |
|---|---|---|
| 访客正常 | 登录与注册按钮显眼；正式聊天输入不可提交 | 登录/注册/浏览公开介绍 |
| 平台暂无真实能力 | “正式能力尚未开放”，不制造假聊天回复 | 浏览说明、注册申请 |
| 认证状态加载中 | 仅显示安全占位，不提前露出用户历史 | 等待确认，不触发重复跳转 |
| 服务异常 | 说明暂无法验证身份，提供重试 | 重试，不回退到冒充生产的演示 |

### 3.2 注册页 `/assistant/register`

**字段**：密码（必填）、确认密码（必填）、昵称（选填）；**无**邮箱、手机号、账号自选框。

| 事件/状态 | 交互规则 |
|---|---|
| 初始 | “创建账号”按钮禁用直到必填内容有效；提示由系统自动分配账号 |
| 密码不足 6 位 | 就地提示“密码至少 6 位”；不提交 |
| 确认密码不一致 | 就地提示；不提交 |
| 弱密码 | [建议] 提示常见弱密码风险；极弱密码由服务端拒绝（口令黑名单） |
| 提交中 | 禁止重复提交，按钮显示处理中；不得在客户端推测账号值 |
| 成功 | 使用服务端真实返回的账号及恢复码跳转成功页；账号唯一 |
| 失败或限流 | 明确展示可重试/稍后再试，不重复创建；429 需提示可重试时间（如已知） |
| 请求超时结果未知 | 不自动再次申请新账号；优先通过安全的申请幂等机制确认原结果 |

**关键安全契约**：数字账号分配由服务端原子保证；展示账号作为**字符串**，不得把位数限制为 3 或把它当普通浮点数运算；登录输入校验仅接受正整数字符串，禁止科学计数法、符号、空白等格式。产品“不设固定位数上限”并不否认底层存储有实际容量，应允许后续平滑扩容。

### 3.3 注册成功页 `/assistant/register/success`

**必须显示**：

1. 本次实际分配的数字账号、复制按钮。
2. 一次性恢复码及“复制/已安全保存”确认区；**只在本次注册成功页面显示一次**，服务端仅保留其验证摘要。
3. 清晰提示“账号待管理员激活”；告诉用户如何查看审核状态。
4. “前往登录/查看审核状态”入口。

**恢复码交互**：[建议] 初次发放**一枚高熵单次使用恢复码**，成功使用后失效并生成下一枚新码；登录态可经重新验证密码主动轮换。恢复码不是 6 位密码，不能使用易猜的纯数字短码。刷新页面后不应再从接口取回明文；若本次注册结果已丢失，不得冒用固定示例账号，显示“注册资料已提交，请使用已保存的账号登录；忘记信息请联系管理员”的受控说明。

**页面退出前**：[建议] 未勾选“我已保存账号与恢复码”时提示确认；提示不是永久阻止退出。不要把恢复码写入 LocalStorage、浏览器 URL、分析埋点或前端错误日志。

### 3.4 登录页 `/assistant/login`

字段：数字账号、密码；辅助链接：注册、忘记密码。登录错误使用不泄露账号存在性的统一文案。

| 登录结果 | 页面去向/文案 |
|---|---|
| 凭据错误 | “账号或密码错误” + 可重试；不要说明账号是否存在 |
| 登录被限流 | “尝试次数过多，请稍后再试” |
| 正确凭据 + Pending | `/assistant/pending` |
| 正确凭据 + Active | 安全 `returnTo` 或 `/assistant` |
| 正确凭据 + Disabled | `/assistant/disabled` |
| 正确凭据 + Rejected | `/assistant/rejected` |
| 首次登录强制改密 | [建议] 进入受限密码更改页面，完成后再放行正式功能 |

**统一身份要求**：Admin、Creator 和 User 使用相同登录入口及服务端会话；原有管理员入口若保留只能作为重定向兼容页。[建议] 初始 Admin 由受信任初始化生成一个数字账号（不消耗普通用户从 100 开始的注册序列），具体保留号码及旧 `admin` 账号迁移方案需单独冻结；不得重新引入第二套身份体系。

### 3.5 Pending、Rejected、Disabled 状态页

| 状态 | 核心信息 | 允许动作 | 禁止动作 |
|---|---|---|---|
| Pending | 账号、待激活说明、无需邮件通知 | 刷新审核结果、退出 | 聊天、模型运行、访问个人正式数据、管理后台 |
| Rejected | 申请未通过及安全可展示说明 | 退出、查看联系方式（若提供） | 反复绕过审核注册或直接重提审批 |
| Disabled | 账号被停用，提供受控求助说明 | 退出、按政策联系管理员 | 继续使用既有会话或执行工具 |

待激活用户点击“刷新审核状态”后若变为 Active，进入 `/assistant`；若仍 Pending，保持页面并提示“尚未激活”。[建议] 自动轮询不是必需，避免频繁请求；可提供手动刷新。

### 3.6 忘记密码 `/assistant/recover`

**主流程**：数字账号 → 输入一次性恢复码 → 输入新密码及确认密码 → 提交验证 → 原恢复码立即作废 → 显示新的恢复码一次 → 所有旧登录会话失效 → 返回登录。

| 状态 | 行为 |
|---|---|
| 缺账号/恢复码 | 必填提示，不校验账号存在性 |
| 恢复码错误/失效/已使用 | 同一类安全文案；限制尝试频率；不暴露状态差异 |
| 新密码不足 6 位/不一致 | 表单内明确提示 |
| 重置成功 | 撤销旧会话，立即失效使用过的码，新码仅显示一次 |
| 丢失恢复码 | 展示“联系管理员辅助恢复”流程说明，不自动绕过验证 |

**管理员辅助恢复**：管理员不能查看用户旧密码和恢复码；只能在完成可信的**线下身份归属核验**后执行受审计的强制重置或生成受控的短期重置凭证。数字账号、昵称、熟悉的聊天内容本身不足以证明身份；无法核实则必须拒绝重置。[待定] 具体线下核验标准、重置凭证交付渠道及有效时长须形成安全运维 SOP，未经确认不可开放无证明的“后台一键接管”。

### 3.7 个人中心 `/assistant/me`

**主导航**：个人资料、账户安全、我的能力、我的 Skill、我的连接、我的文件、使用记录。

| 子页 | 核心动作 | 必须状态 |
|---|---|---|
| 个人资料 | 查看数字账号（不可编辑）、修改昵称 | 保存中/成功/校验错误 |
| 账户安全 | 改密、会话管理、轮换恢复码 | 重新验证后才能执行敏感操作；完成后注销其他会话 |
| 我的能力 | 查看已启用和收藏的能力 | 可用/需授权/暂不可用/已停用 |
| 我的 Skill | 导入、创建、编辑、删除私人 Skill | 草稿/可用/校验错误/归属无权 |
| 我的连接 | 查看平台批准的 MCP Server 的**本人**连接状态 | 未连接/待授权/已连接/过期/失败 |
| 我的文件 | 文件上传、浏览、删除 | 上传中/成功/失败/无权/容量限制 |
| 使用记录 | 本人 Run、错误及反馈 | 排队/执行/终态与原因 |

### 3.8 旧匿名历史认领 `/assistant/me/legacy-import`

入口仅在**当前浏览器存在可核验的旧匿名 Owner 身份**时显示。用户主动选择“查看可认领历史”→展示数量与可能冲突→确认认领→服务端检验 Owner 权利并幂等迁移→展示迁移条数/跳过数。不要自动绑定其他浏览器或其他用户数据。失败不删除旧数据，失败提示可重试。与本人已有会话相同的迁移不能重复插入。

## 4. 用户工作台：真实能力交互

### 4.1 工作台首屏 `/assistant`

**Active 用户**进入后首先看到工作台，而不是固定的示例会话。推荐层级：开始新聊天 → 最近聊天 → 常用/已启用 Agent → 能力入口 → 个人文件与连接状态。

| 首屏条件 | 展示行为 |
|---|---|
| 用户尚无会话 | 空会话引导；不凭空写入演示历史 |
| 平台配置了可用基础 LLM | 可以直接发送普通聊天请求 |
| 平台没有真实可用 LLM | 输入区禁用，说明“模型尚未配置/服务不可用”，提供刷新 |
| 有可用 Agent / Tool | 展示可用能力；执行前仍由后端校验 |
| 能力需要 MCP 授权 | 显示“连接账号”而不是“运行” |
| 能力下线 | 保留历史展示能力快照，但新的调用不可执行 |
| 后端能力目录请求失败 | 展示网络错误和重试，**不自动切换为演示目录当作生产结果** |

### 4.2 四类能力卡片统一契约

每张能力卡片具有：名称、描述、类型、可见状态、就绪状态、必要授权说明、适当的主操作。**严禁仅通过 `published` 决定是否显示“运行”。**

| 能力状态组合 | 主按钮 | 次级说明 |
|---|---|---|
| 已发布 + 允许使用 + 已就绪 | “使用”/“在聊天中启用” | 可选查看详情 |
| 已发布 + 允许使用 + 缺少个人授权 | “连接/授权” | 明确服务名称与授权范围 |
| 已发布 + 无执行权限但简介可见 | “无使用权限”（禁用） | 按政策说明如何申请授权 |
| 已发布 + 依赖失效/模型不可用 | “暂不可用”（禁用） | 提示阻塞原因与刷新 |
| 草稿/审核中 | 正式用户目录不出现 | Creator/Admin 在后台可见 |
| 已停用/退役 | 新目录隐藏或显示只读历史 | 不允许新运行 |
| Demo / 模拟 | 只在独立示例区展示 | 必须明确“演示，不能真实执行” |

### 4.3 Tool `/assistant/tools`

列表：搜索、分类、可用性筛选、能力详情。详情提供输入参数表单（如适用），显示 Schema 校验、授权范围、风险提示。可执行只读 Tool 直接运行；涉及写入/外发/删除的工具，在真正实施前必须经过显式确认与批准的风险策略，不在本 SPEC 中默认为安全。运行后进入本人 Run 详情。

### 4.4 Skill `/assistant/skills`

页面分**平台技能**与**我的技能**两个 Tab。平台技能只能按授权启用；我的技能可从 `.md` 导入、编辑、删除（仅本人）；导入后内容服务端持久化并跨设备可见。必须标识：Skill 提供执行指令与资源，不应把客户端“导入成功”误报为模型已实际执行。用户可在聊天中通过明确选择启用 Skill，实际任务执行需要 Runtime 支持。

### 4.5 MCP `/assistant/mcp`

页面分**已批准服务**与**我的连接**。普通用户不能创建新的 Server 实体或输入任意网络地址。服务卡说明用途、可访问工具、所需授权、连接状态及操作。

| 连接状态 | 行为 | 主操作 |
|---|---|---|
| `unconnected` | 已批准服务可查看，但不能用需要凭据的 Tool | 连接 |
| `authorization_pending` | 已发起授权但未完成 | 继续授权/取消 |
| `connected` | 允许调用本人授权范围内的工具 | 查看工具/断开 |
| `expired` | 原授权已失效 | 重新授权 |
| `failed` | 连接或健康检查失败 | 查看原因/重试 |
| `revoked` | 用户或平台撤销 | 根据政策重新连接或联系管理员 |

授权成功必须由服务端实际验证，不能仅校验 URL 字符串或等待固定 300ms 后标记已连接。断开连接后，新的工具调用立即拒绝。用户 A 的令牌不能用于用户 B。

### 4.6 Agent `/assistant/agents`

详情页说明 Agent 能完成什么、使用哪些 Skill/Tool/MCP、哪些依赖需要用户授权、模型或执行是否就绪。主按钮优先按缺口显示“连接外部账号”“等待恢复”“开始对话”。

Agent 执行创建时锁定发布版本和依赖快照；用户之后看到可以解释的执行步骤及最终状态。不暴露模型隐藏推理内容，也不展示第三方凭据。

### 4.7 聊天 `/assistant/chat/[id]`

发送前校验：Active 身份、当前资源授权、相关 MCP 连接、模型/工具状态、配额与风险确认。输入框中选择的能力只代表选择意图，不是权限凭据。发送后显示流式输出与真实状态，支持停止、失败重试；刷新能恢复持久化历史。

**失败原则**：真实 LLM 不可用、MCP 失败或 Tool 超时时，显示对应错误和下一步，不生成模拟回复冒充成功。运行中停用/撤权需在后续敏感操作前再次检查。

## 5. 管理控制台：交互与状态

### 5.1 导航结构与权限

管理布局侧栏按顺序为：**总览 → 用户与权限 → AI 资源 → Tool / Skill / MCP / Agent → 发布中心 → 运行中心 → 系统设置**。菜单按服务端返回的权限裁剪。Creator 只看到自己有权限的创作与调试功能；Admin 看到完整平台治理。所有后台页提供“返回用户工作台”。

### 5.2 用户管理 `/assistant/admin/users`

首屏指标：用户总数、待激活数、已停用数；默认优先展示“待激活”队列。筛选：账号、角色、状态、注册时间；支持有界分页。列表最小列：数字账号、昵称、角色、状态、注册时间、操作。账号显示为可扩展长度的文本，不截断为三位数。

| 操作 | 交互和状态规则 |
|---|---|
| 激活 Pending | 点击“激活”→确认（建议）→服务端变更→成功后列表/详情/待审核数同步刷新 |
| 拒绝 Pending | 需要填写理由→确认→标记 Rejected，禁止重复操作产生不同结果 |
| 停用 Active | 强提醒其已有登录会话与新执行将失效→填写原因→确认 |
| 恢复 Disabled | 检查恢复条件与权限→确认→状态 Active |
| 分配 Creator/Admin | 显示权限变化范围→二次确认→审计；不能自我越权提权 |
| 重置密码 | 只能走**可信人工核验已完成**的受控流程，不能凭账号一键生成可用密码 |
| 尝试停用最后有效 Admin | 服务端明确拒绝；前端显示无法操作的理由 |
| 状态被其他管理员修改 | 409 冲突，提示刷新后重试，不覆盖别人最新决定 |

**用户详情**：基本信息（不暴露密码或恢复码）、角色、状态变更记录、登录会话元数据（必要时）、安全操作、审核历史。普通 Admin 只能查看履职所需的用户基本资料，不能直接进入用户私人聊天内容。

### 5.3 角色页面 `/assistant/admin/roles`

V1 固定 User / Creator / Admin 三个内置角色，以只读权限矩阵 + 具体用户角色赋予/撤销操作为主。Creator 仅能维护本人负责的能力；User 没有管理端访问权限。若未来支持角色自定义，必须另行定义权限继承和审计，V1 不允许在 UI 看似可编辑却无后端能力。

### 5.4 AI 资源管理

Admin 维护模型服务、模型可用状态、密钥引用、全局配额与风险策略。Secret 必须以引用/掩码展示，不提供读取明文按钮。模型未连接时，发布校验应拒绝声称“可执行”的配置或明确不可就绪，不能以模拟模型测试作为真实通过。

### 5.5 四类能力管理页

共用列表操作：创建草稿、搜索、状态/作者筛选、查看详情、编辑草稿、配置校验、真实测试、提交审核、查看历史；仅 Admin 拥有审批、发布、停用、回滚操作。Creator 对他人资源只按明确授权可见，默认不可修改。

**统一编辑态**

| 状态 | UI 规则 |
|---|---|
| `draft` | 可编辑，标记未发布；显式保存和校验 |
| `validating` | 显示进行中和校验结果；禁用冲突操作 |
| `in_review` | 作者默认不可静默改写已提交审核的快照；需要撤回或创建新草稿 |
| `rejected` | 展示原因，允许作者调整后再次提交 |
| `published` | 展示已发布不可变版本；编辑时生成下一草稿，不改线上版本 |
| `disabled` | 停止新执行；历史版本和运行仍可追溯 |
| `conflict` | 409 冲突时保留当前编辑内容但不覆盖服务器版本；提示对比并刷新 |

Tool 专有配置：输入/输出 Schema、执行器、超时、风险级别、真实测试。Skill：Markdown/资源、依赖、注入提示处理。MCP：服务端点、传输、认证策略、工具发现、工具级权限及真实连接测试；只有受批准的平台服务进入用户目录。Agent：模型、System Prompt、Skill/Tool/MCP 依赖、版本约束、预算、调试与测试结果。

### 5.6 发布中心 `/assistant/admin/releases`

区分“审核申请”和“已发布版本”：

1. Creator 提交审核 → 待审核列表出现。
2. Admin 查看内容、依赖和测试证据 → 同意或驳回（驳回说明必填）。
3. 审核通过后发布**不可变版本**，记录审核人、发布人、时间和变更说明。
4. 发布完成 → 用户目录根据可见范围与授权更新；不得暗自把演示配置当成可运行配置。
5. 紧急停用 → 新运行拒绝；回滚 → 创建可追溯的发布事件并验证旧版本依赖仍可用。

**跨视图一致性**：发布成功的管理端状态、公开目录、执行前授权结果三者必须一致。失败必须明确、不可显示先成功后悄悄撤回的虚假状态。

### 5.7 运行中心 `/assistant/admin/runs`

页面分运行记录与审计记录。运行记录提供时间、用户标识（按权限/脱敏）、能力、版本、状态、耗时、错误类别、Token/工具调用统计（可获得时）、`run_id` 关联；支持筛选和详情。**准入 accepted 与执行 completed 严格区分**。Admin 能看全局运行元数据但默认无权查看私人聊天正文、完整原始提示词、凭据；Creator 只能看本人负责能力的授权范围数据。

## 6. 统一状态体系与展示优先级

### 6.1 身份与账户状态

```text
Guest ──注册成功──> Pending ──管理员激活──> Active ──管理员停用──> Disabled
                           └─管理员拒绝──> Rejected           └─管理员恢复──> Active
```

角色（User/Creator/Admin）与账户状态独立；`Pending + Admin` 也不能绕过激活限制，除非是受信任的初始管理员创建流程。

### 6.2 能力与连接状态

| 层 | 状态 | 用户端含义 |
|---|---|---|
| 生命周期 | draft / in_review / published / disabled | 只有符合发布要求的资源可进入正式可见目录 |
| 可见性 | private / assigned_roles / active_users / public_preview | 是否允许看到安全介绍 |
| 权利 | allowed / denied / approval_required | 是否能发起操作，是否需审批 |
| 就绪性 | ready / auth_required / unavailable / degraded | 技术条件是否允许真实执行 |
| 本人连接 | unconnected / authorization_pending / connected / expired / failed / revoked | 是否满足个人 MCP 凭据条件 |

### 6.3 用户端操作优先级（不可显示互相矛盾的按钮）

**优先级从高到低**：账户非 Active → 没有资源可见性 → 资源未发布/已停用 → 使用权不足 → 需要确认/审批 → 需要个人授权 → 依赖或模型不可用 → 预算不足 → 可以执行。

例如用户没有权限且 MCP 还未连接，主按钮先提示**无使用权限**，不引导用户完成毫无意义的 OAuth 授权；有权限但连接失效时主按钮显示**重新授权**。

### 6.4 Run 执行状态

```text
queued -> running -> completed
                 ├-> failed
                 ├-> cancelled
                 ├-> timed_out
                 ├-> waiting_authorization -> running / cancelled / timed_out
                 └-> waiting_approval      -> running / cancelled / timed_out
```

补充规则：

- 同一 Run 只能有一个终态；重复完成事件不能覆盖终态。
- 取消成功、失败、取消请求被拒绝须明确区分。
- 失败重试应生成新的执行尝试/Run 关联，不应把旧失败记录直接改为成功。
- 页面刷新后状态从服务端恢复；网络断开时显示连接中断，不推断任务已失败。
- 每个状态提供用户可见的下一步（继续授权、等待批准、重试、查看错误）。

## 7. 通用页面状态、错误与可访问性规范

### 7.1 通用状态表

| 状态 | 展示要求 | 操作要求 |
|---|---|---|
| Initial | 不显示过期示例数据作为正式结果 | 可开始真实加载 |
| Loading | 骨架/进度；避免闪现错误权限页面 | 禁止重复提交 |
| Empty | 明确说明为什么空，例如“暂无已批准的 MCP 服务” | 提供合法下一步，不造假记录 |
| Ready | 展示当前有效数据和适用权限 | 主操作可见且真实可用 |
| Success | 告知成功的具体对象与后果 | 数据刷新、避免重复提示 |
| Validation Error | 字段级错误与可修复说明 | 保留已输入内容 |
| Forbidden | 权限不足，不泄漏私有对象详情 | 返回合法入口 |
| Conflict | 数据版本已变化，保存前须重新核对 | 不静默覆盖 |
| Unavailable | 服务/模型/连接不可用 | 可重试或查看原因，不能模拟成功 |
| Rate Limited | 请求频繁 | 显示合理恢复提示 |
| Session Expired | 登录已过期/停用 | 保留非敏感草稿，转统一登录或状态页 |

### 7.2 服务错误与产品文案

| HTTP 语义 | 页面处理 |
|---|---|
| 400/422 输入或业务校验 | 字段或业务原因明确提示；不清空输入 |
| 401 未登录/会话失效 | 安全地进入统一登录/状态页；必要时保留站内 returnTo |
| 403 无权限 | 权限不足提示；不可仅用隐藏按钮替代后端鉴权 |
| 404 私人资源不存在或无权访问 | 统一“不存在或无法访问”；防 ID 枚举 |
| 409 状态/版本冲突 | 重新加载并呈现冲突，不覆盖现有数据 |
| 429 限流 | 禁止继续自动重试，提示稍后再试 |
| 500/502/503 运行或服务异常 | 标明不可用并提供安全重试；绝不虚构成功结果 |

### 7.3 交互与视觉一致性

- 统一消息区分：系统结果、权限警告、个人授权、真实执行步骤；不要复用“模拟成功”视觉表现。
- 关键按钮具有清晰动词（注册、激活、连接、提交审核、发布、运行、停用、退出），避免所有按钮叫“确定”。
- 破坏性操作含影响范围与确认；重要成功可检查到状态变化。
- 表单、弹窗、抽屉支持键盘操作、焦点返回、可读标签和错误定位。
- 颜色不作为唯一状态线索：同时展示文字/图标；移动端无需手动输入隐藏后台地址。
- 对恢复码和密钥不提供无授权的“显示历史明文”能力。

## 8. 页面间关键流程（跨端契约）

### 流程 F1：游客注册并被激活

`/assistant` → `/assistant/register` → 服务端真实分配账号和恢复码 → `/assistant/register/success` → 保存账号/恢复码 → `/assistant/login` → `/assistant/pending`；Admin 在 `/assistant/admin/users` 激活 → 用户刷新状态 → `/assistant` 正式工作台。

验收：注册账号跨三/四位正常；Pending 正式接口拒绝；管理端与用户端状态一致；无需邮箱/短信。

### 流程 F2：管理员进入后台并管理角色

统一账号登录 → 工作台顶部头像菜单“管理控制台” → `/assistant/admin/users` → 用户详情 → 分配 Creator → 审计写入 → Creator 下次权限刷新后看到“能力创作中心”。

验收：普通用户手输后台 URL/API 无法越权；不能停用最后一个有效 Admin；管理员无独立第二套登录。

### 流程 F3：个人 Skill 创建与使用

Active 用户 → `/assistant/skills` → “我的技能” → 导入/编辑 Markdown → 服务端保存 → 在聊天中选用 → Runtime 真实加载 → 本人 Run 可查；跨设备登录可访问，其他用户不可访问。

验收：Skill 导入不只存在于 localStorage；未经授权不得通过 ID 读取别人 Skill。

### 流程 F4：MCP 平台批准与用户连接

Creator/Admin 注册 MCP Server → 真实安全检查与工具发现 → Admin 审核批准并发布 → 用户 `/assistant/mcp` 看见服务器 → 自己授权/连接 → Agent/Tool 使用自己的凭据 → 断开后新调用被拒绝。

验收：普通用户没有“添加任意 Server URL”；用户之间无凭据串用；连接失败不显示已连接。

### 流程 F5：Agent 完整执行与追踪

Creator 创建 Agent 草稿（指定模型/Skill/Tool/MCP 依赖）→ 配置测试→审核发布→ Active 有权用户查看所需授权→完成授权→聊天发起→真实 Run→结果/步骤/错误持久化→用户历史与后台脱敏运行视图可对应。

验收：真实执行不回退演示；版本和依赖可追踪；后台 accepted 不冒充 completed。

### 流程 F6：忘记密码并恢复

`/assistant/recover` → 数字账号+未使用恢复码→设定至少 6 位新密码→所有旧会话失效→旧码作废且只展示新码一次→新密码登录。无有效恢复码时仅进入受控人工核验流程。

验收：重复使用旧码失败；凭空知道账号不可重置；管理员看不到恢复码明文。

### 流程 F7：旧匿名历史认领

Active 用户在原浏览器打开 `/assistant/me/legacy-import` → 服务端验证旧 Owner 身份 → 展示数量 → 用户确认 → 幂等迁移 → 已登录其他浏览器可见迁移结果。

验收：无旧 Owner 凭据无法认领；拒绝认领不会丢数据；重复导入无重复消息。

## 9. SPEC 验收矩阵（用例编号）

| ID | 验收场景 | 预期结果 |
|---|---|---|
| UI-01 | Guest 从个人网站进入助手 | 看到欢迎页及可发现的注册/登录入口；不自动创建演示聊天 |
| UI-02 | 注册密码 5 位 / 6 位 | 5 位被拒绝，6 位满足最低长度校验（仍受弱密码策略约束） |
| UI-03 | 连续注册跨号段 | `998、999、1000` 等账号正确显示/输入，客户端不限制位数 |
| UI-04 | 注册成功且刷新成功页 | 仅初次展示真实恢复码；刷新不能从接口再次获取明文 |
| UI-05 | Pending 登录并尝试聊天/API | 进入状态页，聊天和运行 API 拒绝 |
| UI-06 | Admin 激活 Pending | 管理端刷新，用户刷新状态后进入工作台 |
| UI-07 | Admin/Creator 入口 | 头像菜单/个人中心可见相应管理入口，后台可返回工作台 |
| UI-08 | User 直接输入后台 URL/API | 被拒绝；无用户/权限信息泄漏 |
| UI-09 | Admin 修改角色 | Creator 仅能查看自身授权模块和资源，权限变更生效 |
| UI-10 | 密码找回 | 恢复码单次使用、旧会话失效、新恢复码一次展示 |
| UI-11 | 无恢复码尝试重置 | 只能走管理员可信人工核验；不能凭账号重置 |
| UI-12 | User 查看 MCP | 只能连接已批准服务，不存在任意 Server URL 添加入口 |
| UI-13 | MCP 授权失效 | 显示需重连；服务端拒绝新工具调用 |
| UI-14 | 新用户空工作台 | 无伪造聊天、伪造能力或模拟模型成功回复 |
| UI-15 | 能力已发布但未就绪 | 显示禁用态和具体原因，不允许假执行 |
| UI-16 | Creator 提交审核 | Admin 可审，Creator 可看进度但不能自行发布 |
| UI-17 | 发布 v2 时用户使用 v1 | v1 继续稳定，发布后新请求按新版本执行；历史版本可追溯 |
| UI-18 | 能力停用 | 新执行被服务端拒绝，旧历史保留 |
| UI-19 | 用户 A/B 访问私有资源 | A 不可访问 B 的会话、Skill、MCP 凭据和 Run |
| UI-20 | 旧匿名历史认领 | 合法认领一次且幂等，未授权不能盗取 |
| UI-21 | 真实 Run 失败/取消/超时 | 用户/管理员看到一致终态、原因和下一步，非模拟成功 |
| UI-22 | 未授权的运行详情 URL | 不泄漏运行存在性和敏感内容 |
| UI-23 | 服务错误/超时/限流 | Loading/Empty/Error/Rate limited 均能理解并重试，无重复破坏动作 |
| UI-24 | 移动端后台与用户端入口 | 点击可见、可返回，不依赖鼠标悬停，页面无不可操作溢出 |

**本 SPEC 的出阶段条件**：UI-01～UI-24 的需求有明确页面归属、状态与验收标准；具体 E2E 自动化脚本将在 `04-端到端业务验收.md` 中展开。完成本文件**不表示已完成代码验收**。
