## 0. 本文的目的和不变约束

本文件将前三份产品规格转换为**跨角色、跨页面、跨服务的可核查业务验收场景**，作为后续拆分 Codex 任务、编写自动化测试和实际发布验收的共同基线。

最终不是“页面齐全”或“单元测试通过”，而是验证两个完整闭环：

- **用户业务闭环**：游客 → 数字账号注册 → Pending → 管理员激活 → Active 登录 → 发现/授权能力 → 使用 → 保存个人历史。
- **平台运营闭环**：Creator 创建/测试 → Admin 审核/发布 → 按权限分发 → 真实执行 → Run/审计 → 停用、升级或回滚。

**不可改变的已确认规则：**

1. 数字账号从 `100` 开始逐次递增，`999 → 1000`、`9999 → 10000`，无产品层面的固定位数和人数上限；账号不复用。
2. 不接邮箱、短信、第三方身份服务。密码**至少 6 位**；不得将本期最低长度偷偷改为 8 位。
3. 注册默认 `User + Pending`，只有管理员激活后可使用正式服务。
4. 忘记密码支持**一次性恢复码 + 受控管理员辅助**；恢复码只显示一次，服务端不得存储明文。
5. 普通 User 只能连接**平台已批准的 MCP Server**，不得自行提交任意 Server URL。
6. 同一账户体系服务 User、Creator、Admin；管理员入口必须在 UI 中可见、管理 API 由服务端鉴权。
7. 演示数据、模拟连接与模拟回复不能冒充正式能力/真实运行结果。
8. 用户私有会话、文件、Skill、MCP 凭据和 Run 必须隔离；Admin 治理权限不等于私有正文读取权限。

## 1. 验收层次、通过标准与证据

### 1.1 四类测试证据

| 层次 | 用途 | 可采用的环境/数据 | 不得替代 |
|---|---|---|---|
| L1 API / 单元 | 状态机、权限、事务、并发、拒绝场景 | 隔离数据库、可控时钟、Fake 依赖 | 不能证明浏览器导航体验 |
| L2 浏览器 E2E | 角色菜单、注册/审核/跳转、空/错状态、跨浏览器 | 真正的前后端+独立浏览器 Context | 不能证明第三方连接真实有效 |
| L3 集成 | Tool Executor、MCP Client、LLM 流式与运行记录 | 受控测试 Tool、测试 MCP Server、Fake LLM | 不能宣称已验证真实供应商 |
| L4 预发布真实联调 | **真实模型、真实已批准 MCP、真实执行**，生产 HTTPS 配置与迁移 | Staging、测试账号、受限凭据与预算 | 不能用 Mock 结果冒充真实完成 |

[建议] 每个用例至少记录：用例编号、代码/部署版本、运行环境、执行角色、输入或夹具（不含密钥）、预期、实际结果、证据链接、执行时间、结论、缺陷编号。

### 1.2 判定规则

- **PASS**：前置条件成立，所有关键断言通过，且证据可以重现。
- **FAIL**：实际行为与已确认规则或验收断言冲突。
- **BLOCKED**：上游决策、外部服务或环境缺失；**不可算 PASS**。
- **NOT_RUN**：未执行；不可用 PR 描述或截图代替。
- **NOT_APPLICABLE**：经记录确认的非目标范围用例；不能用来跳过 V1 必需能力。

**完成定义**：前端效果 + 后端真实权限 + 持久化与状态 + 失败/越权路径同时成立。浏览器按钮隐藏但 API 仍可越权，判 FAIL；API 只返回 accepted 而无真实执行，判 FAIL；仅 Fake Provider 跑通，真实供应商验收仍为 BLOCKED。

### 1.3 建议的发布门禁

| Gate | 产品可交付结果 | 必须覆盖的用例 | 放行前提 |
|---|---|---|---|
| G0 安全与决策 | 密码恢复、首次管理员、生产访问、安全预算有操作规则 | 文末待冻结项 | 关键安全决策不再含糊 |
| G1 身份闭环 | 注册、激活、统一登录、角色、私人数据归属和迁移 | U-01～U-17 | 业务/API/浏览器均验证 |
| G2 资源治理闭环 | 创建、测试、审核、发布、权限、个人 Skill/MCP 授权 | C-01～C-10 | 不再将 Demo 当正式能力 |
| G3 真实执行闭环 | 至少一个真实 Agent 链，真实 Tool 与 MCP、可追踪 Run | R-01～R-06 | L4 真实联调通过 |
| G4 上线与回归 | HTTPS、运营安全、跨浏览器/移动端与关键回归 | O-01～O-05 | 生产阻塞均解决 |

G1/G2 可以作为**独立阶段成果**验收，但不得因此宣称“完整产品 V1 上线”。完整 V1 需 G0～G4 全部放行。

## 2. 测试角色、数据夹具和执行前提

### 2.1 角色夹具

| 代号 | 含义 | 初始状态与权限 |
|---|---|---|
| `V` | 游客 | 无账户、无正式会话 |
| `P` | 新注册用户 | User / Pending |
| `A` | 用户甲 | User / Active，持有私人会话和资源 |
| `B` | 用户乙 | User / Active，无权访问 A 的私人资源 |
| `C` | 创作者 | Creator / Active，仅拥有自己的平台草稿 |
| `X` | 管理员 | Admin / Active，拥有审核/发布权限 |
| `X2` | 第二管理员 | Admin / Active，用于最后管理员与并发审核场景 |
| `D` | 已停用用户 | User / Disabled |

账号是运行时分配的字符串；**不假设 A 永远等于 100**。唯独“空数据库起始分配”专项测试明确断言 `100`。

### 2.2 服务与资源夹具

- `TOOL_READ`：受控、只读、真实执行的 Tool，返回稳定可核查的结构化结果。
- `SKILL_PRIVATE_A`：A 的个人 Skill；`SKILL_PLATFORM`：平台发布且具有可验证行为影响的 Skill。
- `MCP_APPROVED`：Admin 已批准的测试 MCP Server；`MCP_UNAPPROVED`：未批准服务。
- `CONNECTION_A`：仅属于 A 的个人授权；B 无此授权。
- `AGENT_RESEARCH`：绑定特定模型、Skill、Tool 和可选 MCP Tool 的研究助手。
- 模型分为 `FAKE_MODEL`（自动化可控）、`REAL_MODEL`（预发布真实联调）；测试报告必须区分来源。
- 测试产生的密码、恢复码、API Key、第三方授权 Token **只在安全测试夹具中持有，不上传录屏、CI 日志、仓库或截图**。

### 2.3 环境隔离

- 账号递增/并发测试使用**独立、可重置**数据库，不使用生产实例。
- 两名用户采用独立浏览器上下文；跨设备测试使用第二个真正独立的上下文/会话。
- 验证匿名历史迁移时先准备旧 Owner Cookie 与旧会话，迁移失败后验证旧数据仍在。
- 真实外部联调使用专用测试账户、只读访问范围、最小权限和成本/请求上限。
- 对限流、过期、错误、断网、冲突使用可控测试条件，不依赖不可重复的偶发故障。

### 3.1 U-03 账号跨位数断言细则

- 空库第一笔成功注册：返回**字符串** `"100"`；不是数据库内部主键。
- 连续分配 `...998,999,1000...9999,10000`；输入、URL、安全审计、管理列表都支持更多位数。
- 无产品上的“最多 900 人”逻辑；底层数据库数值精度/存储容量属于技术扩容规划，不能临时截断账号。
- 并发压测不能只观察 API 返回；需核对数据库唯一约束和实际用户记录数。
- 注册请求重试的业务结果必须明确：同一幂等键返回同一注册结果，或在无法确认结果时提供安全的恢复流程；**不能**直接重新发号且声称首次请求失败。

### 3.2 U-05 / U-10 恢复码安全细则

- 恢复码与登录密码是**不同秘密**。最短 6 位仅适用于用户密码，不适用于恢复码强度。
- 恢复码显示时禁止通过 URL、LocalStorage、分析事件或日志泄露；服务端仅保存可验证摘要。
- 重复使用、错误码、过期码以及错误账号使用同一种安全错误语义，频率受限。
- 管理员不能直接查看恢复码或旧密码；没有可信的人工核验 SOP 时，管理员辅助重置项目应标记 **BLOCKED**，不能以“后台一键重置”替代。

## 4. 四类能力的资源、授权和发布 E2E

| **C-07** | P0 | C 创建 Agent，固定模型、Skill、Tool/MCP 工具版本；X 发布 v1，编辑 v2 草稿 | v1 不受 v2 草稿影响；发布 v2 后新 Run 用 v2；旧 Run 可追溯 v1 | C06、UI-17 |

| **C-09** | P0 | 版本已发布但模型、Tool 或依赖不可用；目录请求失败 | 展示正确的不可用/授权原因，按钮禁用；不能返回 Demo 目录、模拟连接或模拟回复 | C10、UI-15 |
| **C-10** | P0 | 测试同一能力“已发布但无使用权 / 需外部授权 / 预算不足 / 未就绪” | 主按钮按 SPEC 的阻断优先级唯一呈现；服务端拒绝与 UI 原因一致 | C03、UI-15 |

### 4.1 关键发布与授权断言

- 发布、可见、个人启用、授权、技术就绪是**不同维度**；发布成功不自动等于可执行。
- Creator 的草稿编辑仅影响自己的资源；审核申请后不得静默改写待审快照。
- Admin 发布时必须校验依赖可用、真实测试证据；发布与审计要么都成功，要么都回滚。
- 平台 MCP Server 的批准和用户个人的连接授权是**两件事**；任何用户都不能共享别人的连接 Token。
- 个人 Skill 不是“客户端导入成功”就等于 Runtime 已加载；必须在真实执行证据中体现其影响。
- 已停用能力可以保留只读历史，但不能绕过前台按钮从 API 新建执行。

| **R-04** | P0 | A 查本人 Run，X 查全局脱敏运行，C 查本人负责能力的汇总 | 状态/版本/耗时/错误/可得用量一致；accepted 不冒充 completed；私有正文和密钥不外泄 | C08、UI-22 |

| **R-06** | P0 | 模型不可用、MCP 故障、工具超时、401/403/409/429/503、网络断开 | Loading/Empty/Error/重试状态清楚，保留安全输入；不会谎称成功，也不无限重试 | UI-23、C10 |

**真实执行证据最小集合**：Run ID、关联会话与消息、发起用户、Agent/能力及依赖版本、真实模型请求的可核查提供商调用标识（安全脱敏）、Tool/MCP 调用名称与结果摘要、状态变化、耗时、错误类别、Token 用量（供应商提供时）。**不要求记录模型隐藏推理**，不得明文持久化外部 Token。

### 5.1 真正的 V1 研究助手验收链

`Creator 配置 → Admin 发布 → A 发现 Agent → A 连接已批准 MCP（如需） → A 提交任务 → Runtime 使用指定 Skill → Tool 真实执行 → MCP Tool 真实执行（如该 Agent 声明必需） → 回复持久化 → 用户 Run 可查 → Admin 脱敏记录可查`。

如果测试 Agent 的产品定义**声明 MCP 为必需依赖**，就必须真的调用 MCP Tool 才能通过；不能将“如需”解释成无条件跳过。  
仅用 Fake Provider 的 CI 成功是 L3 通过，L4 真实联调仍需独立执行并记录。

## 9. 建议的自动化落地顺序（不是 Codex 开发指令）

| 顺序 | 优先建立的可重复测试 | 主要风险 |
