# feat02 R-03 网络恢复

## 1. 问题

真实用户发送消息时，服务端可能已经创建 user/assistant 消息和 Run，但流的 HTTP 连接在客户端收到完整事件前中断。旧客户端会直接提示“消息未保存”，并允许用户重新发送，导致重复消息或误判执行失败。

## 2. 实现

流请求异常后，客户端按同一会话重新读取服务端状态：

- 用本次 `clientTurnId` 查找服务端是否已持久化该 turn。
- 如果已找到，恢复服务端消息和 Run 关联的页面状态。
- 提示网络中断并说明已恢复，不再把它当作“未发送”。
- 如果服务端未找到该 turn，仍保留原网络错误和安全重试路径。
- 服务端仍是执行状态权威，前端不会自行把 Run 标为 completed。

## 3. 验证

- 新增 Vitest：模拟服务端已回传 `start` 后流连接断开，验证客户端重新读取会话、恢复两条消息、保留 `generating` 状态并显示恢复提示。
- Runtime 错误恢复与真实用户重试 E2E：桌面/移动共 4 条通过。
- 前端全量 Vitest、TypeScript、ESLint 与生产构建通过。
- 完整浏览器断网注入仍为 **NOT_RUN**；不把单元恢复测试写成真实网络故障验收。

## 4. 剩余阻断

R-03 的“等待授权或审批”Run 状态仍需要批准人、授权范围和恢复协议的产品/安全决策，当前保持未实现。R-03 继续为 **PARTIAL**。
